# 単語ペアの抽出・校正基準

単語ペアは、原本 `Src` / `Tgt` の方向を保ち、実際に対比される最小の自立した語全体を選ぶ。共有する文脈は外すが、語の内部を共通文字だけで切らない。`word` と `compound` を単語ペア、`particle-inclusive` と `phrase` を文脈付きペアとして区別する。採否、読み、意味、指示対象は境界とは別に出典で判断する。

## 旧経路と現経路

旧 `scripts/asa2025/extract_word_pairs.py` は MeCab の分かち書きに `SequenceMatcher` を適用し、非共通トークンの連続区間をペアにした。現在の `corpus_api/pair_workflow.py` は原文オフセットと構造化注釈を保持し、トークン差分に加えて全文比較も機械候補にする。全文候補は見落とし防止のためであり、校正済みの比較単位とは限らない。機械候補の `UnitType` とレビュー後の `UnitType` は異なってよい。今回のレビューはエージェントによる校正であり、研究者による承認を示さない。

旧経路の chiVe 語彙フィルタ、括弧の一律削除、ローマ字距離による除外は復活させない。後続校正にあった同音の一律除外も行わない。原本11列、出典、確認済み読み、意味・識別注釈、採否を保つ。

## 比較範囲と種類

1. 両側で共通する左右の文脈を外し、別々の差分は別々のペアにする。`その人に幸福をもたらす…／その人に交付金をもたらす…` は `幸福／交付金`、`欧州問題が／欧州本体が` は `問題／本体` を `word` とする。後者と同じ原本にある別の差分も残す。
2. 辞書に全表面の見出しがある自立語・固有名詞、または原資料が一語として明示する対は `word`。名詞だけに限らず、自立動詞・形容詞・副詞も対象にする。`ひろい／しろい` は `word`。`書いた／描いた` のような活用形は、共通の時制助動詞を外すと非自立の語幹になるため、活用形全体を候補にする。
3. 全体が一つの辞書見出し・固有名として確定しない名詞連続や、接辞を含む構成を比較する対は、必要な最小範囲を `compound` とする。`回避姿勢／回避性` の `性` は接尾辞であり、`姿勢／性` を `word` としない。反対に、`三角橋／参宮橋` は地名全体を取り、共通の `橋` だけを落とさない。辞書に全体の見出しがないことだけでは単語でないと判定しない。
4. 助詞が対立に不可欠なときは `particle-inclusive`。左右の長さは独立で、`舞台が／豚肉` に存在しない `豚肉が` を補わない。節、述語連鎖、並列句、片側が句断片になる対は `phrase`。`聞き分けのない女の頬を／父は毛のない女の頬を` は共通の `のない女の頬を` を外して `聞き分け／父は毛` とし、右が句断片なので `phrase` とする。この対の文脈読みは `キキワケ／チチワケ`。後者の助詞「は」を文字どおりハとは読まない。出典説明の括弧は発話本文と区別する。
5. 同音異義語、同表記の別語義・別指示対象を残す。同一表記と同一読みだけでは除外しない。同じ語の単なる表記揺れかどうかは出典の文脈と語義で確認する。

MeCab の分割や共通文字の有無は候補である。複数の名詞が続くというだけで `word` とせず、句読点、助詞、複数の述語がある対を機械的に単語集合へ入れない。逆に文字数だけで長い固有名詞を除外しない。

## 読みと注釈

`PairSpans` は原文の Unicode 文字単位の半開区間で、左右を独立に指定する。括弧が読みや識別注記なら `Override` で分類し、発話内容なら範囲に残す。広い全文 `Override` の内側だけに短い `PairSpan` を置くと注釈を途中で切るため、短い比較単位に対応する注釈へ組み替える。

読みの `confirmed` は原資料の明示、文脈に適合する正確な辞書項目、または根拠を記録した研究者判断で支える。旧全文読みの任意の部分文字列、MeCab の最適経路、pykakasi の推定を新語の確定読みにしない。助詞「は」「へ」「を」の発音は書字と異なる場合がある（[文化庁の説明](https://www.bunka.go.jp/kokugo_nihongo/sisaku/joho/joho/kakuki/03/tosin03/index.html)）。機械的な範囲短縮を確定できるのは、両側の新語全体と旧注釈・辞書の読みが一意に対応し、音便・連濁・多読・括弧注記・固有名詞の解釈を損なわない場合だけ。対応できない行は原資料と辞書を個別に調べる。全表面の辞書見出しがない `交付金` も、原本の対比と語構成・読みを確認して校正済み `word` にできる。機械下書きは保守的な `compound` 候補でよい。

## 出力と訂正の追跡

無指定の `/v1/pairs` は校正済みの採用・除外行を返し、各行に採否を含める。一方 `/v1/pairs/export` は採用行のみを出力する。両入口の検索条件は共通で、追加の `unit_group=lexical` は校正済み `word` + `compound`、`unit_group=contextual` は `particle-inclusive` + `phrase` を選ぶ。単語ペアCSVの明示入口は `/v1/pairs/export?format=csv&unit_group=lexical`。既存の `unit_type` 単一選択も維持し、両フィルタを指定したときは積集合とする。

旧runと原本CSVを上書きせず、新しいrunで再生成する。全旧採用ペアについて、原本ID・旧PairID・旧範囲/表面/種類・新範囲/種類・読み根拠・採否・変更理由・確認者を監査表で対応づける。同じ対の訂正は既存PairIDを維持し、分割・統合は新IDから `SupersedesPairID` で旧IDを辿れるようにする。レコード数、ペア数、変更、不変、保留、除外を別々に数える。

未解決は機械候補や推測読みで埋めず、争点、確認した原資料・辞書、残る候補と理由を行ごとに残す。未調査と、調査後も決められない状態を区別する。構文・件数検証の成功を、比較単位や発音の研究上の確定と取り違えない。
